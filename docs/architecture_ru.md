# Аудит архитектуры и аппаратуры

Основа: upstream `7e3196193997bd6a4644610c41d54a76eff88760` (main на момент начала работы). История и исходные лицензии сохранены. Работа выполняется в `geek1o/epd-nrf5`; upstream remote имеет отключённый push URL.

## Поток данных

`main.c` → RTC/app_timer раз в секунду → `m_timestamp` → `ble_epd_on_timer` → событие `app_scheduler` → `epd_gui_update` → `DrawGUI` → страничный буфер → `write_image` драйвера → full refresh → sleep дисплея → отключение GPIO EPD.

Рендер не выполняется внутри timer IRQ. В исходной версии календарь обновляется при `timestamp % 86400 == 0`, часы — при `% 60 == 0`. Русская версия отслеживает успешно поставленный в очередь номер суток/минуты. Если очередь занята в полночь, событие повторяется в следующую секунду; после приёма повторов в том же периоде нет. Синхронизация и старт дают принудительное обновление. После синхронизации счётчик хранит местные секунды: Unix UTC плюс смещение. Таймер запускается заново при SET_TIME, поэтому первая секунда после синхронизации начинается с нового интервала. В русской сборке неподтверждённое время блокирует автоматические обновления; после reset экран запрашивает синхронизацию.

Новый `GUI/calendar.c` не зависит от Nordic, libc time, malloc, BLE или шрифтов. Он рассчитывает даты, понедельник = 0, количество дней месяца, ISO-недели, классы дней и ближайший фиксированный праздник. `GUI/GUI_RU.c` отвечает за компоновку и символы. `GUI/fonts_ru.c` содержит только выбранные глифы. Исходные `GUI.c`, `Lunar.c/.h`, `fonts.c/.h`, `tools/build_fonts.py` и `tools/font.txt` сохраняют китайскую конфигурацию. В исходном `thisMonthMaxDays(uint8_t year, ...)` год сужается; русская версия использует `uint16_t` и полное правило 100/400 лет.

## Память и настройки

`EPD_config.c` использует Nordic FDS: запись с `file_id=0`, `record_key=1`. Хранятся модель, GPIO, LED, wakeup pin, режим, начало недели и другие исходные поля; структура и протокол не расширялись. При обновлении существующая запись сохраняется. При её отсутствии применяются исходные аппаратные настройки, для RU начало недели по умолчанию 1. Русский рендерер всегда использует понедельник, даже если старая настройка содержит 0. Команда начала недели остаётся совместимой для китайской конфигурации.

Время не пишется во Flash каждую секунду/сутки. `time_valid` — новое поле только в промежуточной `gui_data_t`, не во Flash и не в BLE-пакете. Сброс обнуляет признак синхронизации. Это исключает выдачу произвольного стартового timestamp за правильную дату.

GFX выделяет один heap-буфер; для трёх цветов делит его на две плоскости, для четырёх использует 2 бита/пиксель. Русская версия сохраняет этот механизм, освобождает буфер после рендера и проверяет malloc. Для GCC добавлен `_sbrk` с границей `__HeapLimit`; исходный libnosys `_sbrk` границу не проверяет. nRF51 heap = 2800, stack = 1200; nRF52 heap = 8192, stack = 2048. Размеры статической RAM, heap и stack учитываются раздельно, включая резерв SoftDevice.

## Энергосбережение

Основной цикл выполняет scheduler и исходное `idle_state_handle`/Nordic power management: CPU спит между событиями, RTC работает. После отрисовки EPD уходит в sleep; waveform и тайминги контроллеров не менялись. Календарь делает одно штатное полное обновление в полночь; синхронизация/переключение режима/перезапуск добавляют принудительное обновление.

Deep sleep — отдельная команда System OFF; RTC и BLE прекращают работу, пробуждение эквивалентно reset. При истечении advertising timeout исходный код входит в System OFF только в режиме картинки с настроенным wakeup pin; календарь остаётся с RTC, но у такой платы advertising может ждать внешнего пробуждения. В стандартной Hema-конфигурации wakeup pin `FF`, advertising перезапускается. BLE не отключён и его интервалы не менялись.

LFCLK использует внутренний RC, так как наличие кварца неизвестно. Это ограничивает точность длительного автономного хода; измерений ppm и тока на устройстве нет. Внешний кварц нельзя включать по названию ценника.

Семь GPIO перечислены в исходном порядке `EPD_config.h`: это не рекомендация применить их к неизвестной плате. Runtime nRF52 выбирает defaults по FICR PART. Сохранённая FDS-конфигурация имеет приоритет. Вендорские платы могут отличаться; радиомодуль с тем же SoC не гарантирует распиновку.

Для 400×300 есть модели `01` (UC8176 ч/б), `03` (UC8176 три цвета), `04` (SSD1619 ч/б), `02` (SSD1619 три цвета), `05` (JD79668 четыре цвета). Также upstream содержит 5,83″ и 7,5″ панели. `EPD_driver.c` задаёт модель/разрешение/цвет, `SSD16xx.c`, `UC81xx.c` выполняют команды. Образы не выбирают новый контроллер по внешнему виду: runtime model из настроек остаётся прежним.

## BLE и OTA

Сохранены UUID, команды, структура конфигурации и передача изображений/RLE. SET_TIME `0x20`: четыре байта big-endian Unix UTC, затем int8 UTC hours и режим. При отсутствии hours RU использует +3, ZH +8. Сборка RU сообщает версию `0x1b`, китайская — исходную `0x1a`. Веб показывает локальное время устройства как UTC-форматированный civil timestamp, чтобы не добавить часовой пояс браузера второй раз.

SDK12 и SDK17 используют разные интеграции secure DFU. Приложение лишь переключает в существующий bootloader. Оно не может установить, каким ключом продавец собрал bootloader, и BLE-подключение не подтверждает OTA. Подробности и обнаруженная неопределённость готовых HEX — в [инструкции](flashing_ru.md).
