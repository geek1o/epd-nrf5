# Проверки и ограничения

Дата работы: 21 октября 2026 года. Физического устройства в окружении нет; BLE-радиоканал, ток, drift RTC и обновление реальной панели не проверялись.

## Исходная сборка

До изменений приложения собран upstream `7e3196193997bd6a4644610c41d54a76eff88760` для nRF52 с Arm GNU 12.2.1. Изменений в GUI/main/EPD для этого запуска не было: скрипт извлёк исходный список Keil, заменил startup и обработчик ошибки на GCC-варианты SDK и использовал nano newlib. Итог: text 69 640 байт, data 440; полный адресный образ приложения 70 080 байт. [Журнал](validation/baseline-nrf52.log).

Исходный nRF51 с Keil heap=4000 и stack=1200 не прошёл GCC-link: `region RAM overflowed with stack`; static 4072 + heap 4000 + stack 1200 > 8200 байт доступной приложению RAM. Это ограничение порта GCC, а не отсутствие SDK. Для русской сборки heap уменьшен до 2800; страничный рендер проверен с этим значением. Размер stack сохранён. 128-КБ nRF51 не поддерживается этой веткой.

## Автоматизированные проверки

- `tests/test_calendar.py`: 49 673 даты 1970–2105, преобразования туда/обратно, 23:59:59 → 00:00:00 следующего дня, понедельник первым, ISO-неделя и её год против Python datetime; 2000/2024/2028 високосные, 2100 невисокосный.
- Праздники РФ и исключения 2025–2027: рабочие субботы, перенесённые выходные, 247 рабочих дней в каждом году; fallback 2028 без переноса соседнего года.
- `tests/test_refresh.c`: переход полуночи, повтор после заполненной очереди scheduler, отсутствие повторных обновлений в течение суток, режимы часов и картинки.
- `tests/test_web.js`: фактический `syncTime` из веб-интерфейса, точные байты SET_TIME, московская полночь, отрицательное смещение и отказ от молчаливого округления дробного часового пояса.

- Каждый основной кадр сравнивается побайтно для heap 2800 и 8192: проверены швы страниц и полное совпадение изображения. Проверяется наличие всех русских глифов, включая Ё/ё, и UTF-8 измерение текста. Host-only assertions проверяют горизонтальные и вертикальные границы текста. Отдельно проверена новая компоновка по референсу владельца: сетка слева и дата с ближайшими праздниками справа. Они обнаружили длинную строку запроса синхронизации; строка сокращена и проверка повторена.

## Размеры и предупреждения

Резерв SoftDevice отдельно: 8184 байта RAM на nRF51, 8920 на nRF52. Размеры текущих образов, RAM и исходный коммит записаны в `artifacts/manifest.json`.

Точные размеры и SHA256 финальной сборки записаны в `artifacts/manifest.json` и `application-info.json` внутри архива; полные журналы — в `docs/validation/`. Flash считается по полному BIN с инициализаторами `.data`, а не только по колонке text или выводу `--print-memory-usage`. RAM учитывает static с выравниванием, весь heap, весь stack и отдельный резерв SoftDevice.

Обе русские сборки линкер проверяет относительно области, оставляющей загрузчик и FDS нетронутыми. Для nRF52 приложение ограничено 57 344 байтами Flash и 15 656 байтами RAM сверх SoftDevice, для nRF51 — 132 096 и 8200 байтами соответственно. High-water mark стека на реальном MCU не измерен; программные проверки не заменяют эту проверку.

Предупреждений в новом календаре/рендерере/шрифтах при `-Wall -Wextra -Werror` нет. В Nordic SDK остаются известные места: fallthrough в `fds.c`; GCC12 array-bounds при linker-section символах в `app_util.h`/`nrf_fstorage.c`. Их существование подтверждено исходной сборкой. Макросы SDK с expansion-to-defined подавлены отдельным `-Wno-expansion-to-defined`; остальные предупреждения не скрыты. Исходные vendor-файлы ради их устранения не менялись. Они требуют внимания при аппаратной проверке, особенно инициализация FDS и BLE SoftDevice RAM.

## Воспроизводимость

`tools/install_toolchain.py` скачивает четыре Debian-пакета по фиксированным URL, проверяет SHA256 и распаковывает без root в отдельный префикс. Команда:

```sh
python3 tools/install_toolchain.py --prefix ../arm-gnu
ARM_GCC=../arm-gnu/usr/bin/arm-none-eabi-gcc python3 tools/build_firmware.py --chip 52
```

Путь ARM_GCC должен быть абсолютным, если префикс находится вне текущего рабочего каталога. В CI используется абсолютный путь. Для произвольного рабочего каталога скрипт сборки переходит в корень проекта.

Нативный bdfconv взят из U8g2 `d6c8499c5f2707cac8eccd09fd8f677d12b17977`, каталог `tools/font/bdfconv`, собран host gcc. Первоначальные BDF WenQuanYi сохранены для китайского режима. По просьбе владельца русский дизайн переведён на DejaVu Sans: включены подмножества исходных TTF и промежуточные BDF; Pillow 12.3.0 растеризует их с порогом 128, bdfconv упаковывает глифы. Текстовые размеры 11/13/16 px содержат по 162 глифа, цифровые 20/48 px — 10 и 11. Суммарно 8573 байта bitmap-массивов, включая исходный числовой шрифт Helvetica заголовка часов. Все 66 русских букв проверяются реальным декодером в трёх текстовых размерах.

## Что необходимо проверить на ценнике

Идентификацию SoC/памяти/панели, распиновку и сохранение старой FDS; RAM/стек с SoftDevice; работу трёхцветного waveform, время BUSY и отсутствие остаточного изображения; соединение BLE и загрузку изображения; переход местной полуночи без телефона; пробуждение из System ON и отдельное поведение System OFF; точность за несколько суток; расход тока на CR2450; ключ/версию/вместимость и восстановление DFU. Для iPhone Bluefy указан как рекомендация upstream, а не как проверенный в этой работе клиент.
