# Что полезного найдено на GitHub

Срез от 21 октября 2026 года. Исследование выполнено через публичный GitHub API без изменений чужих репозиториев. Upstream сообщает 196 форков; API вернул 182 доступных публичных репозитория. Для 58 выбранных форков проверено сравнение с upstream `main`: 36 имеют собственные коммиты, 20 только отстают, два совпадают. Собственный форк исключён. Изучены изменения и первичные документы перспективных направлений; полный аудит каждого форка не проводился.

Ниже ссылки закреплены на просмотренных коммитах. Заявления авторов об испытаниях на железе приведены отдельно от наших программных проверок. Чужой код не запускался, аппаратные параметры и BLE-протокол нашей прошивки не менялись.

Практический приоритет: сначала подтвердить аппаратную ревизию и сохранить конфигурацию/резервную копию; затем при необходимости адаптировать Windows-клиент. CRC-передачу стоит делать отдельным изменением с тестами обеих сторон и панели. Эти расширения не включены в текущие образы: исходные команды BLE и загрузчик сохранены.

## Что проверено и не перенесено

- [flying9802](https://github.com/flying9802/EPD-nRF5/tree/f3c8d1ad11c07dacde7822caafa1c920a5f737fe) добавляет SSD1673 для 2,13″ 250×122. Это другая панель.
- [Hema 2,13″](https://github.com/jam422470459/EPD-nRF52-hema213/tree/52698b79e08e8defcfd5f51737b58ff734746a61) подтверждает разнообразие Hema, но его GPIO и настройки не подходят автоматически к 4,2″.
- [tiancheng91](https://github.com/tiancheng91/EPD-nRF5/commit/172b337a5d6df702829114f0de5980e4b3e2724f) увеличивает ожидание BUSY с 30000 до UINT16_MAX. Без измерения нашей панели это может скрыть неисправность; таймаут не изменён.
- [sbdrin](https://github.com/sbdrin/EPD-nRF5/tree/540e9b6f451e791993dac64e1f613681eedab53e) убирает watchdog. Для автономного устройства это нежелательно; watchdog сохранён.
- [CyrusShu](https://github.com/CyrusShu/EPD-nRF5/tree/047be4475c9aa0a2527d43f4469e437461cd045d) добавляет ручной часовой пояс. В нашей версии уже есть проверка целого смещения и Москва UTC+3; копирование не требуется.
- [ATC_TLSR_Paper](https://github.com/atc1441/ATC_TLSR_Paper/tree/3778d296f418c30b05310d86dafa4e3404071cb4) рассчитан на TLSR8359. Его загрузчик/OTA не совместимы с Nordic только потому, что корпус похож.

## Отдельно о размере приложения

Японский форк ограничивает приложение nRF52811 концом `0x26000`, оставляя дополнительную страницу. В нашем включённом SDK17 `dfu/sdk_config.h` явно задаёт `NRF_DFU_APP_DATA_AREA_SIZE=8192`; при загрузчике с `0x29000` это даёт предел `0x27000`, как в нашем linker script. Определение по умолчанию на три страницы в `nrf_dfu_types.h` применяется только при отсутствии настройки. Менять разметку по чужой сборке оснований нет. Размеры наших текущих кандидатов и адреса записаны в [manifest](../artifacts/manifest.json); реальную разметку установленного загрузчика всё равно нужно подтвердить перед записью.

## Что уже сделано в нашем форке

Легенда внизу календаря заменена на номер дня и число дней до конца года. Для годов без официальной таблицы переносов сохранено предупреждение. В календарь добавлен такой же индикатор батареи, как в часы: измеренное напряжение и приблизительное заполнение по исходной кривой, без обещания точного процента CR2450. Дополнительных пробуждений, BLE-команд или обновлений экрана это не создаёт.
