# Выбор прошивки, резервная копия и восстановление

Физическая запись в устройство в рамках этой разработки не выполнялась. Пока точная плата не подтверждена, ни один кандидат не следует считать выбранным для вашего ценника.

## Идентификация до записи

Нужны маркировка SoC (включая вариант памяти), фото платы и шлейфа E-Ink, распиновка SWD/VDD/GND, текущая модель панели и конфигурация GPIO, версия приложения, SoftDevice и загрузчика. Сначала сохраните настройки: подключитесь исходным веб-интерфейсом и скопируйте строку «Конфигурация» и журнал версии. Не нажимайте изменение драйвера, очистку конфигурации или случайные debug-команды. Hema 4,2″ в upstream — nRF52811, но купленный экземпляр может быть другой ревизии.

## Резервная копия через SWD

Если readback protection не установлен и доступен Nordic nrfjprog/J-Link, после определения семейства можно **прочитать** Flash и UICR. Пример для подтверждённого nRF52:

```sh
nrfjprog --ids
nrfjprog --readcode backup-code.hex --family NRF52
nrfjprog --readuicr backup-uicr.hex --family NRF52
sha256sum backup-code.hex backup-uicr.hex
```

Для подтверждённого nRF51 замените семейство на `NRF51`. Сохраните файлы вне компьютера и проверьте ненулевой объём/адреса/повторяемость чтения. Flash-копия включает SoftDevice, приложение, загрузчик, настройки DFU и FDS. UICR нужен отдельно: там адрес загрузчика и аппаратные настройки. Чтение может временно останавливать ядро; после отладки проверьте ход времени.

Если чтение заблокировано, **не выполняйте `--recover`, `--eraseall` или APPROTECT unlock для получения копии**: эти операции уничтожают содержимое. В таком случае полного backup нет; нужно получить штатный образ и способ восстановления у продавца. Для подключения учитывайте напряжение платы и ограничения CR2450: не подавайте программатором питание поверх батареек без проверки схемы. Найдите и подпишите SWDIO, SWCLK, GND и Vref по плате, а не по фото чужой ревизии.

## Кандидаты приложений

| Каталог | Адрес приложения | Ограничение HEX | Требование |
| --- | --- | --- | --- |
| nrf52-ru | `0x19000` | конец ниже `0x27000` | S112 7.3.0 (`sd_req=0x126`), 192 КБ Flash/24 КБ RAM, совместимая nRF52811/52810 плата |
| nrf51-ru | `0x1B000` | конец ниже `0x3B400` | S130 2.0.1 (`sd_req=0x87`), 256 КБ Flash/16 КБ RAM |

Выделенные границы оставляют две страницы FDS перед исходным bootloader: nRF52 bootloader `0x29000`, nRF51 `0x3BC00`. Фактическое расположение загрузчика вашего устройства нужно подтвердить; оно может отличаться. Линкер проверяет Flash, статические данные, heap и stack. Bootloader, MBR, SoftDevice, UICR, DFU settings в HEX приложения отсутствуют.

Бинарные файлы имеют расширение BIN без адресов: не записывайте их по нулю. Используйте адресованный application.hex только после проверки карты памяти и сохранения FDS. Стирание страниц приложения может затронуть исходную прошивку; алгоритм и rollback должны быть согласованы отдельно.

## OTA/secure DFU

Готовятся **application-only** пакеты с `hw_version=51/52`, `sd_req=0x87/0x126`, `app_version=0x1d`. Хеш, размер, поля init packet и ECDSA P-256 подпись проверяются программно. Это не тест передачи по BLE или принятия пакета загрузчиком.

Существенное ограничение upstream: публичный ключ, полученный из уже опубликованного `tools/priv.pem`, совпадает с `SDK/*/dfu/dfu_public_key.c`, но соответствующие 64 байта не обнаружены в сегментах готовых `tools/bootloader/*.hex`. Причина не установлена; это может быть другая сборка/представление данных. Совместимость этих готовых HEX по подписи не доказана. Продавец также мог установить иной ключ. Общедоступный upstream-ключ не является секретом или защитой от сторонних обновлений.

Поэтому наличие DFU service и подписанного ZIP **не даёт разрешения на OTA неизвестного устройства**. До OTA подтвердите семейство, SoftDevice, карту памяти, публичный ключ/принятие пакета существующим загрузчиком, текущую версию и правила anti-rollback, а также наличие резервной копии/SWD-восстановления. Места для dual-bank rollback на малых MCU может не хватать; single-bank DFU может удалить старое приложение до завершения передачи. Запрет версии нельзя обходить произвольным downgrade/debug mode.

После подтверждения совместимости пакет можно передавать Nordic nRF Connect Mobile через существующий DFU сервис. На nRF52 приложение использует Nordic buttonless DFU, на nRF51 — сервис SDK12. Процедура зависит от загрузчика: после перехода устройство может появиться под другим BLE-именем. На устройстве эта последовательность не проверена. Текущий веб-интерфейс не является DFU-клиентом.

Для воспроизведения упаковки без установки BLE-драйверов старого nrfutil:

```sh
python3 -m venv .venv-dfu
.venv-dfu/bin/pip install --ignore-requires-python --no-deps nrfutil==6.1.7
.venv-dfu/bin/pip install ecdsa==0.19.2 intelhex==2.3.0 protobuf==3.20.3 crcmod==1.7 click==8.5.0 cryptography==50.0.2
.venv-dfu/bin/python tools/package_ota.py --chip 52 --application build/nrf52-ru/application.hex --key tools/priv.pem --out build/nrf52-ru/application-ota.zip
```

Для nRF51 замените `52` на `51` и каталог. Проверено с Python 3.12. Скрипт использует модуль создания пакетов Nordic, не запускает старый CLI, которому требуются несовместимые современные BLE/USB зависимости. Ключ в команде — исходный публично опубликованный ключ проекта; не размещайте личные ключи в форке.

## SWD-запись и восстановление

После отдельного разрешения и подтверждения карты памяти можно спланировать запись **только** application HEX, без mass erase и без изменения загрузчика. Не пользуйтесь исходным советом «Erase all» для неизвестного ценника с единственной копией прошивки. Приложение не меняет SWD/APPROTECT или аппаратные выводы восстановления.

Если приложение не запускается, восстановление проводят SWD-программатором из проверенного полного backup с учётом UICR, FDS, DFU settings и страниц MBR. Если protection потребует destructive recover, сначала отдельно согласуют потерю данных. Если backup отсутствует, готовый full HEX от другого ценника не является безопасной заменой. После любого reset/DFU выполните синхронизацию времени и проверьте календарь на границе полуночи.
